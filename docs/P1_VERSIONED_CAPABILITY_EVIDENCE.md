Status: experimental checkout evidence for #9 / #16, stacked on Draft #15.

shipped 1.0 compatibility claim exists.** Historical goldens,

## Explicit capability authority

[`oss/persistence-capabilities.experimental.json`](../oss/persistence-capabilities.experimental.json)
is a repository review table, **not a file added to a saved runtime**. It records
all 16 families, exact schema IDs and canonical schema-document digests, semantic
membership, paths/nested pointers, implemented decoder and serializer anchors,
accepted schema versions, historical fixture/canonical digests and empty explicit
migration edges. The checked-in fixtures are never regenerated by tests.

The provenance separates package `0.2.0.dev0`, persisted semantic epoch
`0.1.0-foundation`, historical tag SHA `a274470…`, exact inspected implementation
SHA `9836827…`, and host-supplied behavior/identity authority. Schema version 1
is a document-family version, not package version 1. Future *shipped v1 capability* values remain null, but the **W1 design choice
is recorded separately** in [the owner decision](../oss/p1-w1-initial-writer-decision.json).
The old inventory's nulls remain unchanged because actual v1 binaries and
stable public exports have not been validated; design selection is not a release.

The table accepts **only** the known baseline epoch and explicit `[1]` for each
family. Oldest readable/newest writable refer to today's implementation, not a
promise for future v1. There are no supported format-changing migration edges.
It records existing OperatorHistory, OperatorAction and LastOperatorAction
missing-version in-memory normalizers; this adds no new tolerance. Stored timeline
schema validation still requires ActualEvent versions even though its standalone
normalizer has a default. Version defaults do not bypass hash/link/metadata checks.
Generic JSON serialization is not itself a schema/integrity-validating writer:
the tests validate selected documents against exact schemas before checking their
serialized bytes, and conformance validates the complete copied snapshot.

## Experimental planning and conformance

`tools.persistence_capabilities` is excluded from wheel/sdist and canonical
`snowfall_life` exports. It offers no new public CLI. A checkout caller supplies
an explicit writer name, epoch, **complete 16-family target map**, and approved
reference sets:

```python
from tools.persistence_capabilities import plan_identity_copy, check_identity_copy

plan = plan_identity_copy(
    source, writer="W1-baseline", target_engine="0.1.0-foundation",
    target_schema_versions=explicit_sixteen_family_map, reference_sets=references,
)
report = check_identity_copy(source, externally_staged_copy,
                             plan=plan, reference_sets=references)
```

`W1-baseline` identifies current-format identity-copy evidence; **the tool does
not authorize a stable v1 writer merely because W1 is now owner-selected**.
Planning validates the entire source
through existing preflight, checks corrections against raw events, and binds
raw-file SHA map, semantic tree, history/capture/operator/correction vectors,
capability-table digest and reference-set digest. Conformance re-plans from source,
rejects altered/stale evidence, requires disjoint roots, validates the target
snapshot and compares **all** evidence and final fingerprints. Both operations
only read. They never stage, migrate, commit, publish or call the mutable migration
registry. Plans are detached dictionaries, not trusted authorization certificates.

W2, package-version-as-epoch, missing/partial/extra/future/noninteger target maps,
corrupt capabilities, broken schema/integrity, unknown runtime manifest,
metadata tampering, altered source/candidate bytes and stale source evidence
fail closed. Same semantic hash with different raw bytes is insufficient.
A test also proves a valid legacy OperatorHistory without `schema_version` can
pass full planning when optional summary metadata is absent, without inserting
that field into the saved file. The older test still proves that stripping it
from a summary-bound tree rejects the stale metadata binding.

The prototype is deliberately an **identity-copy conformance check**. It cannot
validate arbitrary new simulation output, approve a data-shape adapter or prove
old->new transformation. Caller-owned immutable snapshots/exclusive quiescence
remain necessary: fingerprints are not locks and cannot defeat adversarial ABA
races. Git parent/CAS authority, candidate commits, host acknowledgement and
recovery are not implemented by this layer; the transaction RFC remains the
separate implementation gate.

## Concrete first-v1 W1/W2 selection material

| Constraint / executable probe | W1: keep current persisted epoch + schema-v1 | W2: introduce a concrete new format |
| --- | --- | --- |
| Pinned historical 16-family / 15-file archive | Existing readers and serializers pass exact raw/canonical/link vectors. No source rewrite is needed merely to read. | Must retain old decoder, validate actual new target vectors and preserve historical source; no implemented W2 target exists. |
| Package version vs checkpoint epoch | Pre-v1 package already differs from persisted epoch. Keeping the epoch avoids gratuitous format churn. | Renaming to `1.0.0` alone rejects at engine gate; target decoder/semantic meaning must be specified. |
| Envelope in any existing family | Current strict versioned schemas reject an added `format_envelope` (16 tested families). | Requires reviewed target schemas, including all four operator-action variants and nested event/capture resources. |
| New runtime manifest path | Current preflight rejects `format-manifest.json` without writing source. | Needs explicit path, hash-membership and old/new-reader rules; adding a file is not neutral. |
| Historical facts + corrections + captures | Exact bytes and pinned links preserved by the identity copy. | Any changed canonical hashed material requires reviewed re-key/relink old/new proofs; blanket schema bumps are unsafe. |
| Execution summaries | Independently validate non-semantic metadata and raw-file digests; semantic equality alone is insufficient. | Must define rebinding, revision, engine SHA and policy semantics, without silently resealing stale metadata. |
| Operator legacy defaults | Preserve current in-memory defaults, full integrity checks and raw source. | Must retain old decoder and decide explicit output normalization without assuming read permission means rewrite permission. |
| Staging/publication/recovery | Reader use needs no format migration. Identity-copy check is available, but no migration commit/publication is implemented. | Requires approved edge, target writer, synthetic old/new goldens, failpoints, unreferenced candidate proof and host CAS/ack recovery. |

**Owner selection: W1 for the first stable 1.0 writer.** The existing format has
demonstrated lower initial risk; no new-field or mixed-format requirement justifies
W2 for the first release. Keep package SemVer independent from the persisted epoch
and use explicit decoder/writer capabilities. Reconsider W2 **only when a concrete
incompatible data-shape, new semantic epoch or mixed-family format issue actually
arises**; approve a new target/migration before changing historical bytes.

For either choice, propose compatible 1.x readers continuing the approved v0.1.0
baseline and every explicitly supported earlier 1.x writer format; minor/patch
updates must not narrow that set silently. Record any deprecation and reviewed
migration before removal at a major boundary. No numeric lifetime/support window
has yet been approved. Old binaries need not read unknown future formats.
